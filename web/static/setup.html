Set up QAX on GitHub in about 5 minutes

After this, every pull request of your app gets one comment with a decision, and the check fails unless the decision is GO. It runs on GitHub's machines, against an app you are allowed to test. Nothing is written to Jira or Xray.

GOEvery selected case ran and passed, and nothing was confirmed as a blocker. The check passes.
NO-GOA case failed because of the app, or a security bug was proven. The check fails and the comment shows the proof.
NOT PROVENSomething the decision depends on did not run. It is never counted as a pass.

  1. Copy the workflow into your app's repository

    Take ci/github_action_release_check.yml from the QAX repository and save it in your app's repository as:

    .github/workflows/qax-release-check.yml

  2. Add the test cases and the page map

    Commit a cases file (default qa/qax-cases.json, a {"test_cases": [...]} file QAX wrote or you exported) and the project's selectors (config/projects/<project>/selectors.json, made by python main.py map).

  3. Add four repository variables

    In GitHub: Settings → Secrets and variables → Actions → Variables.

    NameWhat to put
    QAX_APP_URLThe staging or preview URL of your app. Only an app you are allowed to test.
    QAX_PROJECTYour project name (the folder under config/projects/).
    QAX_REPOowner/name of the QAX repository.
    QAX_APP_STARTOnly if there is no staging URL: a command that starts the app inside the job, for example python app.py --port 8911. Then QAX_APP_URL is http://127.0.0.1:8911.

  4. Add secrets, only if you need them

    Same page, Secrets tab.

    NameWhen
    QAX_REPO_TOKENOnly if the QAX repository is private: a token that can read it.
    QAX_VAR_USERNAME, QAX_VAR_PASSWORDA test user for your app. Cases refer to them as {{env:QAX_VAR_PASSWORD}}, so the password never sits in a file.

  5. Open a pull request

    The workflow runs by itself. About five minutes later the comment appears and is updated on every push. To try it without a pull request, open Actions → QAX — Release check → Run workflow.

Good to know. A pull request from a fork gets a read-only token, so the comment cannot be posted; the decision is written to the job summary instead. To let NOT PROVEN pass with a warning, set the variable QAX_ALLOW_NOT_PROVEN to true. To change the severity that blocks, set QAX_FAIL_ON (default P1). To keep the cases somewhere other than qa/qax-cases.json, set QAX_CASES_FILE.
Safe by default. The check is read-only and runs with DRY_RUN=true. No AI decides GO or NO-GO: pass, fail and "proven" come from deterministic checks. Run it only against apps you own or are authorised to test.
